## 3. Список знайдених та опрацьованих проблем

1. **Аварійний збій через порушення зовнішнього ключа при видаленні маршруту (Критичний баг):**
   - *Симптом:* спроба видалення маршруту, який використовувався в архівному поході, викликала падіння програми з винятком `SQLiteException: FOREIGN KEY constraint failed`.
   - *Причина:* `CountHikesUsingRoute` перевіряв лише активні походи (`AND IsDeleted = 0`), ігноруючи історію.
   - *Рішення:* запит виправлено на `SELECT COUNT(*) FROM HIKES WHERE RouteId = @RouteId;`. Тепер користувач отримує цивілізоване повідомлення `ValidationException`.
2. **Неможливість запуску тестів у ізольованому середовищі:**
   - *Симптом:* тести перезаписували `hikemanager.db` у папці програми та блокували один одного.
   - *Рішення:* у `DbConnectionFactory` додано конфігурацію тимчасового шляху до БД для тестів (`SetCustomDatabasePath`), а в тестовій утиліті реалізовано автоматичне очищення пулу з'єднань `SQLiteConnection.ClearAllPools()` перед видаленням файлу.
3. **Жорстка зв'язаність (Tightly Coupled Dependencies):**
   - *Симптом:* створення `new ExpenseRepository()` у `ExpenseService` та чотирьох сервісів у `HikeReportExporter` унеможливлювало підміну залежностей.
   - *Рішення:* виконано рефакторинг із впровадженням конструкторів із необов'язковими параметрами (Constructor Injection), зберігши повну зворотну сумісність із формами.
4. **Розбіжність категорій демо-даних із допустимими категоріями валідації:**
   - *Симптом:* у демо-засіванні `DatabaseInitializer` використовувалися категорії «Транспорт» та «Рекреаційний збір», тоді як у `ExpenseService.Categories` допустимими були лише «Проїзд», «Харчування», «Спорядження», «Страхування».
   - *Відзначено у звіті* як рекомендація до стандартизації списку категорій у наступній ітерації.

## 4. Сценарій демонстрації (5 кроків для захисту роботи)

Для швидкої та наочної демонстрації викладачу виконайте наступні кроки в терміналі:

### Крок 1. Перевірка збірки рішення
```powershell
dotnet build HikeManager/HikeManager.sln
```
*Що показати:* Збірка обох проєктів (`HikeManager` та `HikeManager.Tests`) завершується успішно: **`0 помилок, 0 попереджень`**.

### Крок 2. Запуск повного набору автоматизованих тестів
```powershell
dotnet test HikeManager.Tests/HikeManager.Tests.csproj
```
*Що показати:* Виконуються всі **130 тестів**, результат зеленого кольору: **`Passed: 130, Failed: 0, Skipped: 0`**.

### Крок 3. Демонстрація перевірки крайових ситуацій (Edge Cases)
```powershell
dotnet test HikeManager.Tests/HikeManager.Tests.csproj --filter "Category=EdgeCase"
```
*Що показати:* Виконуються 40 параметризованих перевірок границь (ділення на 0, високосний рік 29 лютого, суми 1 000 000 000 грн, захист від SQL-ін'єкцій, довгі рядки, формат телефонів тощо). Усі тести проходять успішно.

### Крок 4. Збір та перевірка звіту про покриття коду
```powershell
dotnet test HikeManager.Tests/HikeManager.Tests.csproj --collect:"XPlat Code Coverage"
```
*Що показати:* Файл `coverage.cobertura.xml` формується у папці `TestResults/`. Шар `DataAccess` має покриття **98.2%**, шар `Services` — **89.3%**, а ключовий модуль `BudgetCalculator` — **100.0%**.

### Крок 5. Запуск застосунку та демонстрація ручного чек-ліста
```powershell
dotnet run --project HikeManager/HikeManager.csproj
```
*Що показати:* Відкривається застосунок `HikeManager`. Показати документ `docs/manual-test-checklist.md`, продемонструвати додавання спорядження (перевірка дублікатів зі сумуванням) та розрахунок бюджету у вкладці «Витрати».
