# Використання інструментів штучного інтелекту (Етап 7: Тестування та QA)

Цей документ фіксує прозорість використання асистента штучного інтелекту під час виконання етапу 7 «Тестування та забезпечення якості» над проєктом **HikeManager**.

---

## 1. Завдання, для яких було використано ШІ

1. **Розвідка та аналіз кодової бази:**
   - Автоматизований аналіз фактичних класів, публічних методів та правил валідації в шарах `Models/`, `DataAccess/`, `Services/` та `Views/`.
   - Зіставлення фактичного коду з документацією `CLAUDE.md` і виявлення розбіжностей (відсутність стовпчика `IsDeleted` у початковому описі схеми, додаткові методи в інтерфейсах).
2. **Проєктування архітектури тестів:**
   - Побудова структури тестового проєкту `HikeManager.Tests` (xUnit, .NET 8 Windows).
   - Створення безпечного механізму ізоляції SQLite-баз на Windows: утиліта `SqliteTestDatabase`, яка створює унікальний файл у `Path.GetTempPath()`, а при завершенні викликає `SQLiteConnection.ClearAllPools()` для скидання системного блокування файлу.
   - Створення фабрики тестових даних `TestDataFactory` (шаблон Object Mother / Test Data Builder).
3. **Генерація модульних, інтеграційних та крайових тестів:**
   - Написання тестів для математичного модуля `BudgetCalculator` (ділення на 0, великі числа, банківське округлення AwayFromZero до 2 знаків).
   - Покриття валідації сервісів (порожні рядки, телефонні регулярні вирази, граничні дати, неприпустимі складності).
   - Написання 14 груп параметризованих крайових тестів (`[Trait("Category", "EdgeCase")]`).
4. **Виявлення та аналіз прихованого багу цілісності даних:**
   - Аналіз поведінки `RouteRepository.CountHikesUsingRoute` при наявності архівних походів (`IsDeleted = 1`).
   - Написання тесту, що падає з `SQLiteException: FOREIGN KEY constraint failed`, і подальше коригування SQL-запиту.
5. **Оформлення документації:**
   - Складання стратегії тестування (`docs/testing-strategy.md`).
   - Складання чек-ліста ручного тестування графічного інтерфейсу (`docs/manual-test-checklist.md`).
   - Оформлення звіту про результати тестування та сценарію демонстрації (`docs/testing-results.md`).

---

## 2. Як перевірено результати (Верифікація)

Жоден фрагмент коду, згенерований ШІ, не приймався на віру без суворої верифікації:
- **Перевірка збірки:** кожен крок супроводжувався виконанням `dotnet build HikeManager/HikeManager.sln`. Збірка завершується успішно з **0 помилок і 0 попереджень**.
- **Автоматизований прогін тестів:** успішне виконання команди `dotnet test` для всього набору — **130 з 130 тестів пройдено успішно (100% Passed)**.
- **Аналіз кодової бази:** за допомогою парсера Cobertura підтверджено фактичні показники покриття коду: **89.3% для Services** та **98.2% для DataAccess** (покриття `BudgetCalculator` становить **100.0%**).
- **Ручна верифікація працездатності:** перевірено роботу застосунку `dotnet run` та відповідність поведінки WinForms інтерфейсу складеному чек-лісту.
- **Чистота репозиторію:** перевірено `.gitignore` — файли тимчасових баз даних `*.db`, артефакти збірки `bin/`, `obj/` та звіти `TestResults/` не потрапляють у Git-репозиторій.
